# randbotd v1.0.0 Release Changelog

### ⚠️ Operator Migration Notice (v1.0.0)

Due to the introduction of cryptographic domain separation between `NodeRole::Headless` and `NodeRole::Voter`, existing key files (`node_key.enc`) generated prior to v1.0.0 will fail key validation upon startup. Automated key migration is intentionally omitted as the network is in pre-consensus phase with no persistent history to preserve.

> ℹ️ **Port Binding Notice**: Stop any running daemon or systemd service first (`Ctrl+C` or `sudo systemctl stop randbotd`), otherwise manual key generation/recovery commands will fail due to UDP port `43210` binding conflicts.
>
> 🔒 **Shell History Protection**: If using `--recover`, execute `set +o history` first so your Gutenberg seed phrase is not saved into shell history!

---

#### ⚡ Option A: The Savage Quick Reset (Automated New Key)
If you do not need to recover a specific seed phrase and just want a fresh key:
```bash
# For systemd / headless service nodes:
sudo systemctl stop randbotd
sudo rm -f /var/lib/randbotd/node_key.enc
sudo systemctl start randbotd

# For local CLI nodes:
rm -f ./node_key.enc
randbotd
```

---

#### 🔑 Option B: Interactive Key Generation / Gutenberg Recovery

##### 🟢 Local Daemon / Voter Nodes:
```bash
# 1. Stop local process (Ctrl+C if running)
# 2. Disable shell history (required if using --recover)
set +o history

# 3. Generate a new voter key:
randbotd --force-new

# OR recover an existing key using your Gutenberg 24-word phrase:
randbotd --recover "word1 word2 ... word24"
```

##### 🤖 Headless / Systemd Infrastructure Nodes:
```bash
# 1. Stop background systemd service to release UDP port 43210
sudo systemctl stop randbotd

# 2. Open root shell & disable history
sudo -i
set +o history
cd /var/lib/randbotd

# 3. Generate new headless key:
randbotd --mode=headless --force-new

# OR recover headless key from phrase:
randbotd --mode=headless --recover "word1 word2 ... word24"

# 4. Restart background systemd service:
systemctl start randbotd
```

## 🔐 Cryptographic Node Role Domain Separation & Immutable Headless Security

- **`NET-06` Cryptographic Node Role Key Separation (`src/crypto/identity.rs`, `src/main.rs`)**:
  - Implemented immutable `NodeRole` (`NodeRole::Headless` vs `NodeRole::Voter`).
  - Key derivation functions now bind node roles using SHA-256 domain separation prefixes (`randbotd_v1_identity_domain_headless` vs `randbotd_v1_identity_domain_voter`).
  - Headless infrastructure nodes derive distinct Ed25519 public keys from voting daemon nodes.
  - Modifying CLI flags from `--mode=headless` to `--mode=daemon` forces a public key change, resetting peer reputation across the P2P swarm and rendering vote-hijack attacks cryptographically impossible.

## 📄 Declarative TOML Configuration Engine & Multi-Network Overlay Routing

- **`NET-03` TOML Configuration File Engine (`src/config.rs`, `src/main.rs`)**:
  - Added TOML config file loader parsing `/etc/randbotd/randbotd.toml`, `./randbotd.toml`, or custom `--config <path>`.
  - Supports configurable options for `port`, `seed`, `external_addr`, `peer`, `state_dir`, `do_not_use_clearnet_peers`, and overlay privacy proxies (`tor_socks_proxy`, `i2p_proxy_port`).

- **Multi-Network Transport Policy & Explicit Proxy Notice (`src/main.rs`, `FUNCTIONALITIES.md`)**:
  - Documented transport routing policy: `.onion` via Tor SOCKS5, `.i2p` via I2P SAM proxy, clearnet via native UDP/DNS sockets.
  - Notice logged when proxies are active: Clearnet peers are NOT routed over Tor/I2P exit nodes because exit nodes block arbitrary P2P UDP ports.

- **`NET-07` Do-Not-Use Clearnet Peers Policy (`src/main.rs`, `FUNCTIONALITIES.md`)**:
  - Added `--do-not-use-clearnet-peers` CLI flag and `do_not_use_clearnet_peers` TOML setting.
  - Suppresses clearnet bootstrap seeds and logs an operator notice requiring imported `.onion` or `.i2p` hidden service seeds to bootstrap.

## 🛡️ Security, Privacy & Maintenance

- **`SEC-01` Mnemonic RAM Storage & Secure Erasure Procedure (`src/crypto/gutenberg.rs`, `src/main.rs`)**:
  - Automatically writes Gutenberg 24-word recovery phrases to `/dev/shm/randbotd_mnemonic_<PID>.txt` with strict `0600` permissions when running non-interactively to prevent mnemonic exposure in `journalctl` logs.
  - **Recommended Secure File Erasure Practice**:
    1. Ensure no program is currently using the file (`lsof /dev/shm/randbotd_mnemonic_<PID>.txt`).
    2. Disable swap memory to prevent RAM paging leaks:
       ```bash
       sudo swapoff -a
       ```
    3. Overwrite with zeroes, truncate, and remove file:
       ```bash
       shred -u -z -n 1 /dev/shm/randbotd_mnemonic_<PID>.txt
       ```
    4. Flush kernel caches to storage:
       ```bash
       sync
       ```
    5. Securely wipe unallocated RAM residues (requires `secure-delete` package):
       ```bash
       sudo sdmem -f -ll
       ```
    6. Re-enable swap memory:
       ```bash
       sudo swapon -a
       ```

- **Kernel Keyring & Systemd Encrypted Credentials (`src/crypto/identity.rs`, `debian/postinst`)**:
  - Removed plaintext passphrase env vars (`RANDBOTD_MASTERPASS`), enforcing Linux Kernel Keyring (`keyctl`) or Systemd `LoadCredentialEncrypted=masterpass:/etc/randbotd/masterpass.cred`.

- **`NET-02` Gossip Seen-Cache Pruning (`src/net/router.rs`, `src/main.rs`)**:
  - Added periodic automatic eviction of seen gossip message IDs older than 1 hour (3600s).

- **Project Tidiness & Line Limits (`build.rs`)**:
  - Refactored helper methods into module files to strictly enforce the 500-line source file limit.
