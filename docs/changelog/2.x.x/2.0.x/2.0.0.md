# Changelog — randbotd 2.0.0

**Released:** 2026-08-14

## Summary

This major release transitions `randbotd` to **v2.0.0** due to breaking changes in CA identity derivation (`CA-ID-01`) and the `CaDeclaration` entity schema (`CA-08`). It also adds IDN / Punycode domain normalization before wire-format DNS queries (`DNS-01`).

> [!WARNING]
> ### ⚠️ Breaking Change & Local State Migration Notice
> As P2P events are not being sent yet, just `rm -rf` your `ca_declarations` (`ca_declarations.json` / state directory records) when multioffer comes and now because ID generation changed.

---

## Breaking Changes & Enhancements

### 1. Composite CA Identity Derivation (`CA-ID-01`)

The deterministic CA identifier (`ca_id`) is now cryptographically bound to both the CA `common_name` and the owner node's public key bytes:

```
ca_id = SHA-256("randbotd_v1_ca_identity_domain:" || common_name || ":" || node_pubkey_bytes)
```

- **Multi-CA Ownership**: Allows a single node identity to operate multiple distinct CAs (e.g. Root and Intermediate CAs) without hash collisions.
- **Cryptographic Binding**: Prevents conflicting ownership claims while preserving single-vote consensus reputation bounds.

### 2. Configurable Certificate Validity & Custom TTL (`CA-08`)

`CaDeclaration` and the `PublishCa` IPC command now include configurable certificate validity parameters:

- **`ttl_seconds: u64`** (defaults to 90 days = `7,776,000` seconds): Used directly to compute certificate validity bounds (`notBefore` and `notAfter`).
- **Micro-TTL Support**: Allows ultra-short lifetimes (e.g., 300s micro-TTLs for ephemeral authorization) up to long-lived validity periods without artificial restrictions.
- **`validity_window(now)` Helper**: Exposes calculation of `(now, now + ttl_seconds)` for downstream certificate issuance builders.

### 3. Punycode / IDN Label Normalization (`DNS-01`)

DNS query packets built via `build_dns_query_packet` now automatically convert non-ASCII Unicode domain labels (such as `randºm`) into RFC 3492 / RFC 5891 Punycode ACE wire format (`xn--randm-cka`) using `idna::punycode::encode_str`.

- Wire-format UDP and DoH queries transmit valid ASCII ACE labels, preventing false `NXDOMAIN` rejections on Handshake and internationalized domains.
- ASCII labels and challenge prefixes (e.g. `_randbotd-challenge`) remain untouched.
