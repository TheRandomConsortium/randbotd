# Changelog — randbotd 2.0.1

**Released:** 2026-08-17

## Summary

This patch release implements **`CA-10`** (Critical Custom X.509 OID Extension Engine) foundations, establishes a clean domain separation across `src/crypto/`, `src/pki/`, and `src/proof/`, and migrates the CA specifications into a modular compound specification suite under `docs/specs/ca/`.

---

## Changes & Enhancements

### 1. Critical Custom X.509 OID Extension Engine (`CA-10`)

- **OID Definition (`src/pki/cert.rs`)**:
  - `OID_CRITICAL_WOT_EXTENSION`: Standardized decentralized UUID OID `2.25.332006307751889903095271628869501346770.1.1` derived from ITU-T X.667 root UUID `f9c616c7-8e4d-4f84-a32e-596b5ada63d2`.
  - Marked criticality flag `WOT_EXTENSION_CRITICAL = true` per RFC 5280.
- **Browser Compatibility Warning (`wot_extension_warning`)**:
  - Emits advisory log notices during CA publication:
    > *"Warning: Every certificate emitted under randbotd PKI includes critical WoT extension `2.25.332006307751889903095271628869501346770.1.1` (UUID: f9c616c7-8e4d-4f84-a32e-596b5ada63d2) and will not work in standard browsers without the randbotd extension or proxy daemon."*

### 2. Codebase Domain Modularization

To ensure strict separation of concerns and maintain repository cleanliness ($\le 500$ lines per file, $\le 9$ items per directory):
- **`src/crypto/`**: Focused exclusively on raw cryptographic primitives (`agility.rs`, `identity.rs`, `gutenberg.rs`).
- **`src/pki/`**: Dedicated PKI & certificate layer:
  - `ca.rs`: Subject metadata (`CaSubjectMetadata`), CA declarations (`CaDeclaration`), and deterministic ID computation (`compute_ca_id`).
  - `cert.rs`: X.509 certificate extension definitions, OID constants, and advisory notices.
- **`src/proof/`**: Domain verification & proof of control protocols:
  - `engine.rs`: Proof challenge creation, retry schedules, and active capability verification.
  - `net.rs`: Wire-format HTTP nonce fetching and DNS TXT record parsing.
  - `overlay.rs`: Tor ALPN TLS and I2P SAM bridge transport drivers.
  - `dns.rs`: Punycode IDN normalizer and wire-format DNS resolver.

### 3. Compound Specification Architecture (`docs/specs/ca/`)

- Migrated the monolithic specification into a modular compound suite:
  - [`README.md`](file:///home/mreugenej7/git/randbotd/docs/specs/ca/README.md): Master index and field mapping diagram.
  - [`01_certificate_definition.md`](file:///home/mreugenej7/git/randbotd/docs/specs/ca/01_certificate_definition.md): RFC 5280 headers, standard extensions, custom WoT OID (`CA-10`), and IEEE 1609.2 mapping.
  - [`02_ca_entities_and_operational_model.md`](file:///home/mreugenej7/git/randbotd/docs/specs/ca/02_ca_entities_and_operational_model.md): CA data model, custodian governance, distributed swarms (`CA-11`), offer catalogs (`CA-12`), and local verification sovereignty.
  - [`03_standards_and_ca12_design.md`](file:///home/mreugenej7/git/randbotd/docs/specs/ca/03_standards_and_ca12_design.md): Standards reference matrix and CA-12 subtable architectural commitments.
