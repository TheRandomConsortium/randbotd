# randbotd v1.2.0 Release Changelog

### 🏛️ `CA-01` Custom Subject Metadata Engine & DB Modularization

Version 1.2.0 delivers **`CA-01`: Custom Subject Metadata Engine**, establishing foundational structures, RFC 5280 validation rules, transactional embedded database subtables, and daemon Unix Domain Socket IPC control for Root and Intermediate Certificate Authorities.

---

## 🚀 Key Improvements & Architecture

### 1. `CA-01`: Custom Subject Metadata Engine (`src/crypto/ca.rs`)
- **Distinguished Name (DN) Metadata (`CaSubjectMetadata`)**: Configurable creation of Root and Intermediate CAs supporting standard attributes: `common_name`, `organization`, `organizational_unit`, `locality`, `state_or_province`, `country`, and `email`.
- **RFC 5280 & ISO 3166-1 Alpha-2 Validation (`CaMetadataValidator`)**:
  - Enforces strict 2-letter uppercase ASCII ISO 3166-1 country codes (e.g., `"ES"`, `"US"`). Rejects invalid format or non-ISO codes.
  - Enforces Common Name length limits (1 to 64 characters per X.509 standards).
  - Enforces path length constraint consistency (`path_len_constraint` permitted only when `is_intermediate == true`).
- **Deterministic CA Identification (`compute_ca_id`)**: SHA-256 derivation over root public keys with domain separation prefix (`randbotd_v1_ca_identity_domain:`).

### 2. Transactional Embedded Database CA Subtable (`src/storage/db/ca_subtable.rs`)
- **Derived Entity Subtable (`ca_store`)**: Maintains in-memory lookup map (`HashMap<[u8; 32], CaDeclaration>`) backed by `ca_declarations.json` JSON persistence.
- **IPC CA Creation**: Exposes `IpcCommand::PublishCa` over daemon Unix Domain Socket (`./randbotd.sock`), enabling CA creation without external tools via standard `nc -U` or socket streams.

### 3. Comprehensive Specifications & Two-Stage Swarm Timeline
- **[`CA_Entities_and_Certificate_Definition.md`](file:///home/mreugenej7/git/randbotd/CA_Entities_and_Certificate_Definition.md)**: Comprehensive spec defining standard X.509 v3 fields, RFC 5280, RFC 8446, IEEE 1609.2, ITU-T custom WoT OID `2.25.332...`, offer catalog structures (`CA-12`), downward-only risk floors (`ACME-05`), and local node verification sovereignty.
- **Two-Stage `CA-11` Rollout**:
  - *Phase 3*: Non-monetary high-availability custodian swarms (0 fees).
  - *Global Phase 9*: Monetized Pay-As-You-Work revenue-share settlement (`PAY-03` Monero splits & `PAY-06` purge refund liabilities).

### 4. Code Base Modularization & Cleanliness
- **Database Refactoring**: Split `src/storage/db/mod.rs` into modular submodules (`ca_subtable.rs` and `sync.rs`), keeping file line counts <= 500 lines and directory item counts <= 9 items.
