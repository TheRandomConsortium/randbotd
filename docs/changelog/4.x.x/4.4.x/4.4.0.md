# Changelog — randbotd 4.4.0

**Released:** 2026-10-13

## Summary

randbotd v4.4.0 introduces the full implementation and runtime deployment of **REP-07 (Heuristic Cluster Ponderation Penalties)**. This release solves the Sybil collusion ring and coordinated review-bombing challenge by coupling individual node demotions with **Heuristic Cluster Penalty Propagation**. By employing an in-memory **Inverted Postings Index** (`domain -> voter -> action`), **Probabilistic Co-Occurrence Sampling** with **Empirical Bayesian Shrinkage**, and a **Non-Blocking Asynchronous FIFO Worker**, randbotd detects correlated voting clusters and applies guilt-by-association penalties in $O(1)$ bounded constant time per candidate, completely eliminating the $O(V^2 \cdot D)$ double-loop bottleneck while preventing out-of-order race conditions.

## Key Features & Enhancements

### 1. In-Memory Inverted Vote Index (`InvertedVoteIndex`)
- In [`src/crypto/vote/cluster/mod.rs`](file:///home/mreugenej7/git/randbotd/src/crypto/vote/cluster/mod.rs), introduced `InvertedVoteIndex` providing $\Omega(1)$ best-case and $O(k_d)$ candidate lookups.
- Maintains in-RAM inverted mappings: `domain -> HashMap<voter, action>` and `voter -> HashMap<domain, action>`.
- Fully integrated into [`Database`](file:///home/mreugenej7/git/randbotd/src/storage/db/mod.rs) and incrementally updated during vote ingestion in [`insert_vote`](file:///home/mreugenej7/git/randbotd/src/storage/db/subtables/vote_subtable.rs), avoiding disk/JSON deserialization during clustering checks.

### 2. Probabilistic Co-Occurrence & Bayesian Shrinkage
- Solves the Jaccard set-asymmetry flaw (where master accounts with broad activity evade detection when paired with focused puppet accounts).
- Evaluates directional agreement only on shared voting paths, bounded to at most $M_{\text{sample}} = 64$ lookups ($O(1)$ bounded time in RAM).
- Applies **Empirical Bayesian Shrinkage** with prior constant $k_0 = 5.0$ and significance gate $K_{\text{min}} = 3$:
  $$\text{Sim}(u, v) = \text{Agreement}(u, v) \times \left( \frac{|\mathcal{S}|}{|\mathcal{S}| + 5.0} \right)$$
- Prevents small-sample false positives while reliably catching coordinated collusion rings ($\text{Sim} \ge 0.70$).

### 3. Decoupled Two-Stage Write Path & Asynchronous FIFO Worker
- **Write Path 1 (Synchronous & Immediate)**: Primary vote validation and database persistence remain non-blocking for IPC and P2P gossip relay.
- **Write Path 2 (Sequential Background Worker)**: Demotion events emit a `ClusterJob` into a bounded `tokio::sync::mpsc` channel.
- A single background actor consumes jobs in **strict FIFO order**, preventing out-of-order race conditions, memory stomping, and adversarial timing attacks.

### 4. Damped Cluster Penalty Propagation
- Integrated into [`compute_and_update_voter_ponderation`](file:///home/mreugenej7/git/randbotd/src/crypto/vote/lazy.rs). When a node is demoted by $\ge 5$ points, its cluster peers dynamically receive an attenuated penalty:
  $$\text{Pen}_{\text{cluster}}(v) = \text{round}\Big( 0.50 \cdot \text{Sim}(u, v) \cdot \Delta_{\text{demotion}}(u) \Big)$$
- Strictly enforced **1-hop bounded radius** prevents runaway recursive cascades.

### 5. Formal Specification & Documentation
- Published specification [`docs/specs/reputation/04_rep07_heuristic_cluster_penalties.md`](file:///home/mreugenej7/git/randbotd/docs/specs/reputation/04_rep07_heuristic_cluster_penalties.md).
