# Changelog — randbotd 4.3.0

**Released:** 2026-10-08

## Summary

randbotd v4.3.0 delivers the full implementation and runtime deployment of **REP-05 (CA Rating Propagation Engine)** and completes **REP-06 (Bi-Directional Image Cleaning)**. This release solves the high-order reputation propagation challenge across Certificate Authorities and their issued domains by adhering strictly to a **Ground-Truth On-Demand Lazy Evaluation Architecture**. A CA's public reputation is computed in real time as the consensus-weighted average of trust scores across all active, issued domains. Furthermore, this version integrates dynamic logarithmic $\pm \Delta_{\text{CA}}$ tolerance windows and instant image cleaning via domain purges (`CA-07`), eliminating caching artifacts and statistical desynchronization while maintaining execution latency in the order of microseconds.

## Key Features & Enhancements

### 1. CA Rating Propagation Engine (`REP-05`)
- **Ground-Truth On-Demand Evaluation**:
  - In [`src/crypto/vote/ca_rating/mod.rs`](file:///home/mreugenej7/git/randbotd/src/crypto/vote/ca_rating/mod.rs), implemented `evaluate_ca_rating(&self, ca_id, phonebook) -> Result<CaRatingEvaluation, String>`.
  - Discovers all issued leaf certificates and domains associated with the CA from [`list_cert_chains`](file:///home/mreugenej7/git/randbotd/src/storage/db/subtables/cert_subtable.rs).
  - Evaluates active domain trust on-demand using pre-cached voter weights from [`Phonebook`](file:///home/mreugenej7/git/randbotd/src/net/phonebook.rs) ($O(1)$ per vote), executing in strictly linear time ($O(N_{\text{total\_ca\_votes}})$) and completing in microseconds.
  - Aggregates domain scores using community consensus ponderation weighting:
    $$\text{Rating}(\text{CA}) = \frac{\sum_{d \in \mathcal{D}(\text{CA})} W(d) \cdot \text{TrustScore}(d)}{\sum_{d \in \mathcal{D}(\text{CA})} W(d)}$$
  - Preserves neutral baseline $50.0\%$ when no votes or domains exist (per `ACME-02`).

### 2. CA Dynamic Tolerance Window ($\pm \Delta_{\text{CA}}$)
- Derived from total vote participation across all issued domains:
  $$\Delta_{\text{CA}} = 50.0 \times \left(1.0 - \min\left(1.0, \frac{\ln(1 + N_{\text{total\_ca\_votes}})}{\ln(1 + \max(1, N_{\text{active\_nodes}}))}\right)\right)$$
- Naturally starts at $\pm 50.0\%$ (neutral confidence $[0.0\%, 100.0\%]$) and narrows logarithmically as votes accumulate, solidifying the CA's reputation bounds.

### 3. Bi-Directional Image Cleaning via Domain Purge (`REP-06`)
- Excludes certificates revoked in CRLs and domains actively purged via cryptographic [`DomainPurgeRecord`](file:///home/mreugenej7/git/randbotd/src/storage/db/subtables/purge_subtable.rs) (`CA-07`).
- When a CA operator purges an attacker or compromised domain, on-demand evaluation excludes the offending domain on the very next query, restoring the CA's public reputation instantly without cache staleness or administrative intervention.

### 4. IPC & Command Center Integration
- **IPC Command**: Added `IpcCommand::GetCaRating { ca_id_hex }` in [`src/net/ipc/mod.rs`](file:///home/mreugenej7/git/randbotd/src/net/ipc/mod.rs) and handler in [`src/net/ipc/handler/ca/mod.rs`](file:///home/mreugenej7/git/randbotd/src/net/ipc/handler/ca/mod.rs).

- **Formatting**: Introduced `print_ca_rating` in [`src/cli/format.rs`](file:///home/mreugenej7/git/randbotd/src/cli/format.rs) with human-readable and raw JSON display modes.
