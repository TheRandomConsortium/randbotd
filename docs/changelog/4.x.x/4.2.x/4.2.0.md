# Changelog — randbotd 4.2.0

**Released:** 2026-10-07

## Summary

randbotd v4.2.0 delivers the full implementation and runtime deployment of **REP-04 (Lazy Evaluation Engine)**. This release solves the high-order combinatorial explosion problem ($O(n^m)$) inherent in decentralized Web-of-Trust graph traversal by establishing a decoupled **Write/Read Split Architecture**. Domain consensus states and peer behavioral ponderation weights ($P(u) \in [0, 100]$) are updated and cached incrementally on the write path (upon vote ingestion), enabling on-demand domain trust evaluations to execute strictly in $O(n)$ time. Additionally, this version implements dynamic $\pm \Delta$ tolerance window calculations that naturally rescale when active network node count expands, supporting fair-band ACME matching.

---

## Key Features & Enhancements

### 1. Lazy Evaluation Engine & Write/Read Split Architecture (`REP-04`)
- **Decoupled Write Path (Incremental Caching)**:
  - In [`src/crypto/vote/consensus.rs`](file:///home/mreugenej7/git/randbotd/src/crypto/vote/consensus.rs), introduced `DomainConsensus`, `ConsensusDirection` (`TW`, `UTW`, `UNDECIDED`), and `DomainConsensusCache`. Calculates weighted vote sums, majority direction, and statistical confidence $\sigma(d) \in [0.0, 1.0]$.
  - When votes are ingested via gossip ([`handle_vote_packet`](file:///home/mreugenej7/git/randbotd/src/net/router/broadcast/vote.rs)) or local IPC ([`handle_cast_vote`](file:///home/mreugenej7/git/randbotd/src/net/ipc/handler/vote.rs)), voter ponderation is computed from cached domain consensus and recorded in the peer's profile (`PeerEntry.ponderation_score`).
- **O(n) On-Demand Read Path**:
  - Implemented `DomainTrustEvaluation` and `evaluate_domain_trust_with_weights` in [`src/crypto/vote/lazy.rs`](file:///home/mreugenej7/git/randbotd/src/crypto/vote/lazy.rs). Evaluates domain trust by looking up cached voter weights in $O(1)$ and aggregating active votes in $O(n)$ without recursive graph traversals.
- **Dynamic Tolerance Window ($\pm \Delta$) Rescaling**:
  - Implemented `calculate_dynamic_delta(active_votes, network_nodes)`.
  - Begins at $\pm 50.0\%$ (neutral baseline per `ACME-02`) when zero votes exist, and narrows logarithmically as domain votes accumulate.
  - Automatically rescales (widens) when total active network node count $N_{\text{active\_nodes}}$ expands, guaranteeing fair confidence tolerance windows.

### 2. IPC & CLI Command Center Integration
- Added IPC endpoint `GetDomainTrust` in [`src/net/ipc/mod.rs`](file:///home/mreugenej7/git/randbotd/src/net/ipc/mod.rs) and handler in [`src/net/ipc/handler/vote.rs`](file:///home/mreugenej7/git/randbotd/src/net/ipc/handler/vote.rs).
- Extended CLI command `randbotctl vote trust --domain <domain>` in [`src/cli/main_ctl.rs`](file:///home/mreugenej7/git/randbotd/src/cli/main_ctl.rs) with human-readable and JSON formatters in [`src/cli/format.rs`](file:///home/mreugenej7/git/randbotd/src/cli/format.rs).

### 3. Formal Specification & Documentation
