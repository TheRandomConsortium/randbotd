# Changelog — randbotd 4.1.1

**Released:** 2026-09-30

## Summary

randbotd v4.1.1 introduces the mathematical formulation, input metrics, and verifiable evaluation engine for **REP-03 (Behavioral Score & Weight Ponderation)**. This release formalizes the game-theoretic rules and data structures required for local, decentralized voter weight evaluation, establishing a multi-dimensional scoring function bounded in $[0, 100]$ that neutralizes Sybil review-bombing, bullshit event spam, rapid oscillation attacks, and collusion rings. Dynamic execution of this formula is decoupled and prepared for on-demand lazy evaluation under upcoming REP-04.

---

## Key Features & Enhancements

### 1. Behavioral Score & Weight Ponderation Formulation (`REP-03`)
- **Decoupled Architecture**: Formalized `PonderationInputs`, `PonderationBreakdown`, and `PonderationEngine` in [`src/crypto/vote/ponderation.rs`](file:///home/mreugenej7/git/randbotd/src/crypto/vote/ponderation.rs).
- **Multi-Factor Input Metrics**:
  - `active_votes_count` & `total_votes_emitted`: Quantifies historical voter maturity.
  - `bullshit_events_count` & `valid_events_count`: Enforces ledger-level accountability from anti-entropy logs.
  - `is_equivocator`: Immediate zeroing of voting weight for cryptographically proven double-signing (`PAYLOAD_TYPE_EQUIVOCATION_PROOF`).
  - `consensus_alignment`: Evaluates directional alignment ($\text{Align} \in [-1.0, 1.0]$) with established peer consensus.
  - `rapid_flips_count` & `burst_clusters_count`: Penalizes anomalous high-frequency flips ($\Delta t < 300\text{s}$) and multi-domain flooding bursts.
  - `high_ponderation_affinity` & `low_ponderation_agreement`: 2-pass correlation model rewarding alignment with reputable nodes while penalizing correlation with low-score clusters.
  - `target_concentration_hhi`: Penalizes single-target brigading (Herfindahl-Hirschman Index $> 0.6$).
- **Neutral 50 Baseline Preservation**: Preserves the $[0\%, 100\%]$ fair-band matching confidence spectrum ($50\% \pm \Delta$) without breaking baseline initializers.
- **Headless Role Enforcement**: Implements Manifesto §2.IV isolating headless infrastructure nodes (`is_headless = true`) from voter pool weight ($P(u) = 0$).

### 2. Comprehensive Specification & Documentation
- Published formal specification [`docs/specs/reputation/01_rep03_behavioral_ponderation_formula.md`](file:///home/mreugenej7/git/randbotd/docs/specs/reputation/01_rep03_behavioral_ponderation_formula.md) detailing master formulas, boundary conditions, and classical attack mitigations.
