# Changelog — randbotd 4.1.0

**Released:** 2026-09-29

## Summary
randbotd v4.1.0 delivers the complete implementation of REP-02 (1-Vote-Per-Node Dynamic Reputation Voting & Web-of-Trust state machine) alongside retrocompatible Proof-of-Work challenge extensions for domain purges (CA-07). This release empowers active nodes to cast, flip, retrieve, and broadcast consensus domain reputation votes with real-time mind-change support, logarithmic flip penalty scaling, 1-year monotonic rolling window cooldowns, unresolvable hash protection via changing fields/extra nonces, and strict headless node voting prohibitions. External applications (such as Juanita Banana) can query existing domain votes via new dedicated IPC endpoints without issuing redundant challenges.

---

## Key Features & Enhancements

### 1. 1-Vote-Per-Node Dynamic Reputation Voting (`REP-02`)
- **State Machine & Invariants**: Enforces exactly 1 active vote per node per domain. When a node flips its assessment (`TW` <-> `UTW`), the new vote supersedes the prior vote while the total active vote count on the domain remains constant.
- **Logarithmic Flip Penalty**: Scales Proof-of-Work difficulty sublinearly using $P_{\text{flip}}(\text{revisions}) = 2 \cdot \lfloor\log_2(\text{revisions} + 1)\rfloor$, preventing exponential computational explosion while discouraging frivolous flipping.
- **Monotonic Rolling Window Cooldown**: Anchors active vote counts and revision history in the preceding resolved event's timestamp with a 1-year rolling window (`ACTIVE_VOTES_ROLLING_WINDOW_SECS = 365 * 86_400`). Old votes and flips cool down deterministically across all peers without susceptibility to clock-drift cheating.
- **Difficulty Cap Defense**: Enforces a strict upper bound of 255 bits (`MAX_COMPUTABLE_DIFFICULTY`). If required difficulty reaches or exceeds 256 bits, mining is halted with an explicit directive instructing the user to vote on other domains to allow flip penalties to cool down.
- **Unresolvable Hash Defense**: Integrated `extra_nonce: u64` and `PowEngine::solve_with_changing_field` to eliminate challenge traps when cycling through 32-bit nonce space.

### 2. Headless Node Voting Restriction & P2P Gossip Gating
- **Role Enforcement**: Nodes configured in headless mode (`--mode=headless` / `NodeRole::Headless`) are prohibited from casting consensus votes locally via IPC/CLI (`randbotctl vote cast`) and remotely across P2P gossip.
- **Handshake Role Tracking**: Peer entries in the phonebook record whether remote nodes are headless (`is_headless: bool`). Incoming `PAYLOAD_TYPE_VOTE` gossip messages from headless peers are rejected before ingestion.
- **Monotonic Continuity Gating**: Remote vote packets are rejected if the preceding monotonic vote sequence has not been ingested yet (`vote_seq != prev.vote_seq + 1`), preventing out-of-order state pollution.

### 3. External Vote Retrieval & IPC Integration for Juanita Banana
- **`GetVote` Endpoint**: Added `IpcCommand::GetVote { domain }` returning a structured `DomainVoteStatus` payload:
  - `has_voted: bool`: Indicates whether the local node has already cast a vote for the domain.
  - `my_vote`: The active `VoteRecord` of the local node.
  - `revisions_on_domain`: Active mind-change flips on the domain within the 1-year window.
  - `total_active_votes`, `tw_count`, `utw_count`: Network-wide vote aggregates.
- **CLI Management**: Added `randbotctl vote cast`, `randbotctl vote get`, and `randbotctl vote list` subcommands with formatted table output.

### 4. Retrocompatible Domain Purge PoW Resilience (`CA-07`)
- **Extra Nonce Support**: Added `extra_nonce: u64` with `#[serde(default)]` to `DomainPurgeEvidence` and `DomainPurgeRecord::new_with_extra_nonce`.
- **Legacy Compatibility**: Defaults to `0`, ensuring existing stored purge records in `domain_purges.json` and on-wire messages deserialize and verify identical challenges and sign payloads without migration overhead.
- **Modularized Purge PoW Engine**: Extracted purge challenge generation and difficulty solving into `src/pki/purge/pow.rs` while re-exporting all public symbols from `src/pki/purge/mod.rs`.

## Retrocompatibility Guarantees
- **Storage Subtables**: `domain_votes.json` and `domain_purges.json` operate with additive schemas. Legacy purge records without `extra_nonce` automatically default to 0 and verify cleanly against existing cryptographic signatures and PoW challenges.
- **P2P Wire Protocol**: `PAYLOAD_TYPE_VOTE` (0x06) integrates cleanly into existing gossip broadcasts with seen-cache deduplication and anti-entropy synchronization.
- **CLI Commands**: All preexisting `randbotctl ca`, `cert`, `purge`, and `crl` interfaces remain 100% backwards-compatible.
