# Changelog — randbotd 4.0.1

**Released:** 2026-09-28

## Summary

This patch release abstracts and modularizes the Proof-of-Work engine (`REP-01`), establishing a reusable, algorithm-agile cryptographic puzzle foundation in `src/crypto/pow.rs` shared across Bad-Domain Purges (`CA-07`), upcoming Dynamic Voting (`REP-02`), and CA Flagging (`REP-08`). It also formalizes the per-originator monotonic difficulty consensus architecture in `FUNCTIONALITIES.md` to avoid global blockchain assumptions across asynchronous P2P peers.

---

## Key Features & Enhancements

### 1. Proof-of-Work Challenge Engine Modularization (`REP-01` / `src/crypto/pow.rs`)
- **Algorithm-Agile Engine**:
  - Implemented `PowEngine`, `PowAlgorithm` (defaulting to `Sha256`, extensible for memory-hard schemes such as Equihash per roadmap), `solve_pow`, `verify_pow`, `leading_zero_bits`, and `calculate_logarithmic_difficulty`.
  - Exported `pub mod pow` from `src/crypto/mod.rs`.
- **Deduplication of CA-07 Purge PoW**:
  - Refactored `src/pki/purge/mod.rs` to delegate challenge hashing, difficulty scaling, puzzle solving, and nonce verification directly to `crate::crypto::pow`.
  - Maintained 100% retrocompatibility for all existing purge functions, database subtables, and IPC handlers.

### 2. Formally Documented Voting Difficulty Consensus Model (`REP-01` & `REP-02`)
- **Decentralized Originator Monotonicity Invariant**:
  - Documented why PoW difficulty cannot depend on global cross-network state without creating race conditions or false peer rejections.
  - Formalized the voting difficulty formula:
    $$D_{\text{vote}} = D_{\text{base}} + 2 \cdot \lfloor\log_2(N_{\text{active\_votes}} + 1)\rfloor + P_{\text{flip}}(\text{revisions\_on\_domain})$$
  - Documented causal challenge binding to $(originator \parallel prev\_hash \parallel domain \parallel vote\_action \parallel seq)$ to prevent pre-mining and Sybil review-bombing.
  - Marked `REP-01` as 🟢 in `FUNCTIONALITIES.md`.
