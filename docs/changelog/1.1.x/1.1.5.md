# randbotd v1.1.5 Release Changelog

### ⚔️ Equivocation Detection, Truth Resolution & Anti-Entropy Synchronization

Version 1.1.5 introduces an Equivocation Detection and Truth Resolution engine in `Database` to handle double-signing (e.g. Node A sending a bullshit `seq=5` followed by a true `seq=5`).

---

## 🚀 Key Improvements & Architecture

### 1. Equivocation Detection & Truth Resolution (`src/storage/db/mod.rs`)
- **Double-Signing Detection**: When an event arrives with `seq <= expected_seq`, `Database` checks for an existing event at that sequence number. If the signature is valid but the payload hash differs, **Equivocation / Double-Signing** is detected.
- **Truth Resolution**: If the existing event was marked `is_bullshit: true` and the incoming event has a valid `prev_hash` matching the canonical chain, the incoming event **replaces** the bullshit event at sequence 5, restoring the cryptographic link so subsequent sequences can proceed normally.
- **Persistent Ledger Penalty**: An `EquivocationProof` containing both signed entries is permanently recorded in `event_log` (`payload_type = PAYLOAD_TYPE_EQUIVOCATION_PROOF`) marked `is_bullshit: true`.

### 2. Zero Ad-hoc Emission / Pure Anti-Entropy Sync
- **No Third-Party Gossip Overhead**: Nodes do not need to actively broadcast custom ad-hoc claims about other nodes lying.
- **Stateless & Deterministic**: Standard anti-entropy range sync and Merkle tree drills sync all signed events across all peers. Every receiving node independently verifies Node A's double-signatures and arrives at the exact same ponderation score statelessly.

### 3. Memory Safety Limit
- **Staging Cap**: Enforced `MAX_STAGED_EVENTS = 50` per originator in `pending_unverified` to prevent memory exhaustion (OOM) attacks from malicious peers flooding out-of-order sequence numbers.
