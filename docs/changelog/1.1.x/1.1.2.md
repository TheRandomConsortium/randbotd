# randbotd v1.1.2 Release Changelog

### 🛡️ Anti-Entropy Hardening & Anti-Spam Security Suite

Version 1.1.2 introduces comprehensive security countermeasures against Merkle computation DoS attacks, unsolicited response injection, sequence fragmentation, UDP MTU overflows, and peer spamming.

---

## 🚀 Key Improvements & Security Countermeasures

### 1. Merkle Sub-Root LRU Caching (`src/storage/db/merkle.rs`)
- **DoS Hash Mitigation**: Added `merkle_cache` to `Database` (`RwLock<HashMap<([u8; 32], SequenceRange), Option<[u8; 32]>>>`).
- Prevents CPU-burning DoS attacks from malicious nodes issuing infinite `MerkleDrillRequest` calls. The cache is automatically cleared when new verified events are appended to the event log.

### 2. Anti-Spam Nonce Tracking & Peer Ban Engine (`src/net/history.rs`, `src/net/router/anti_spam.rs`)
- **Nonce-Bound Drill Exchange**: Added `nonce: u64` field to `MerkleDrillRequest` and `MerkleDrillResponse`.
- **Unsolicited Response Ban (300s)**: If a peer transmits an unsolicited or invalid `MerkleDrillResponse` with an un-tracked `nonce`, `router.ban_peer(src, 300)` automatically blocks and drops all packets from that socket address for 300 seconds.

### 3. Dynamic UDP MTU Byte Budget Counting (`src/net/router/sync.rs`)
- **1024-Byte Payload Budget**: Replaced static originator limits with real-time byte count validation (`serde_json::to_vec(&resp_payload).len() <= 1024`).
- Automatically truncates `entries_for_peer` and `my_vector` to guarantee UDP payloads never fragment or exceed safe MTU boundaries.

### 4. Symmetrical Coverage for 0-Event Peers (`src/net/router/sync.rs`)
- If a peer has 0 events or omits a node in its `RangeSyncRequest`, `find_missing_entries_for_peer` automatically includes stored entries for that node in the response, preventing 0-event peers from losing data.

### 5. Peer Saturation & Continuous Range Suppression (`src/net/router/anti_spam.rs`)
- If a peer transmits a continuous sequence range `[1..N]` for an originator, `router.mark_originator_saturated` records that the peer is fully saturated up to sequence $N$. Redundant drill requests for that originator from that peer are suppressed.
