# randbotd v1.1.4 Release Changelog

### ⚡ Out-of-Order Anti-Entropy Event Staging & Auto-Promotion Engine

Version 1.1.4 introduces an out-of-order event staging buffer (`pending_unverified`) to eliminate rigid "culoduro" in-order ingestion failures over lossy/re-ordered UDP connections.

---

## 🚀 Key Improvements & Architecture

### 1. Out-of-Order Staging Pool (`src/storage/db/mod.rs`)
- **Authenticity-First Verification**: `entry.verify_signature()` is verified *immediately* upon receipt using the originator's Ed25519 public key.
- **Future Sequence Staging (`entry.seq > expected_seq`)**: Out-of-order events (e.g. `seq=5` arriving before `seq=4`) are buffered in `pending_unverified` sorted by sequence number rather than being rejected and dropped.

### 2. Auto-Promotion & Chain Link Validation (`src/storage/db/mod.rs`)
- **Auto-Promotion Engine**: When missing sequence gaps (e.g. `seq=4`) are filled, `append_event` automatically drains and promotes contiguous staged items (`seq=5`, `seq=6`, ...) into `event_log` and persists them to disk (`event_log.jsonl`).
- **Originator Link Verification**: During promotion, `prev_hash` links are strictly verified against the newly extended chain. If an originator published a broken or forged chain link, the corrupted staged sequence is discarded without poisoning the canonical database.
