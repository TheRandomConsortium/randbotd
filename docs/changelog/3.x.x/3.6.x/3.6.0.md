# Changelog — randbotd 3.6.0

**Released:** 2026-09-21

## Summary

This minor release implements **CA-09: Cryptographic Key Rotation & Remediation Engine**, completing a fundamental security, life-cycle, and reputation remediation primitive in `randbotd`. 

In `randbotd`, a Certificate Authority identity (`ca_id`) is cryptographically bound to its owner node identity key and does not hold a single monolithic signing key. Instead, individual **Certificate Offers** (`CertificateOffer`) hold the cryptographic keys and parameters (`KeyAlgorithm`, TTL, coverage scope) used to issue certificates. Version 3.6.0 establishes offer-level key life-cycle management, enabling targeted key rotations for routine operational hygiene or suspected key leakage, while enforcing the **Distrust Reset Invariant**—requiring proven rotation across 100% of a CA's active offers to remediate standing market distrust strikes (`REP-09`).

## Key Features & Enhancements

### 1. Cryptographic Key Rotation & Remediation Engine (`CA-09`)
- **Offer-Level Key Architecture**:
  - Attached an explicit `public_key` field to `CertificateOffer` with default deserialization semantics, maintaining backward compatibility with existing databases.
  - Updated `CaOfferCatalog::compute_hash` to deterministically fold active offer public key bytes into the catalog digest.
- **OfferKeyRotation & Proof-of-Possession (PoP)**:
  - Defined `OfferKeyRotation` capturing `offer_id`, `old_public_key`, `new_public_key`, `key_algorithm`, and a mandatory digital Proof-of-Possession (`proof_of_possession`) signed by the *new* keypair over the canonical PoP challenge payload:
    $$\text{PoP Payload} = \text{SHA-256}(\text{"randbotd\_v1\_offer\_pop\_domain:"} \parallel \text{ca\_id} \parallel \text{offer\_id} \parallel \text{new\_public\_key} \parallel \text{timestamp})$$
  - Immunizes the P2P swarm against key-substitution attacks by cryptographically proving ownership of the corresponding private key before rotation acceptance.
- **Chained Audit Trail (`KeyRotationProof`)**:
  - Implemented sequentially chained `KeyRotationProof` payloads (`rotation_seq`, `prev_rotation_hash`, `timestamp`, `reason`, `rotations`, and `ca_signature`), anchored directly to the CA owner's node identity key.
- **Distrust Reset Invariant**:
  - `KeyRotationProof::can_reset_distrust` validates that 100% of non-draft offers belonging to the CA are renewed.
  - Partial rotations (targeting specific offers for routine hygiene or suspected leaks) succeed and update key material, but leave market distrust strikes active until full remediation is proven.

### 2. Transactional Key Rotation Database Subtable (`key_rotations.json`)
- **Dedicated Subtable & Storage Engine**:
  - Added `rotation_store` and `distrust_store` to embedded `Database`.
  - Atomically applies offer key updates in `ca_offers.json`, recalculates parent CA catalog hashes in `ca_declarations.json`, logs verified events to `event_log.jsonl`, and updates standing distrust strike records.
- **Architectural Streamlining**:
  - Modularized subtable JSON loading via `ca_subtable::load_hex_map_from_disk`, reducing line count in `src/storage/db/mod.rs` to 400 lines (well below the 500-line cleanliness limit).

### 3. Unix Domain Socket IPC Endpoints
- **Operator Key Rotation Control Plane**:
  - Implemented `RotationHandler` handling `PublishKeyRotation`, `GetKeyRotations`, `GetCaDistrustStatus`, and `RecordDistrustStrike`.
  - Supports automatic local signing and key generation with Proof-of-Possession or ingestion of pre-formed JSON proof payloads.

### 4. P2P Swarm Gossip Integration (`PAYLOAD_TYPE_KEY_ROTATION = 16`)
- **Gossip Verification & Propagation**:
  - Registered wire payload type 16 for network-wide key rotation broadcasts.
  - Ingestion in `handle_key_rotation_packet` independently verifies CA owner node binding, sequence continuity, proof-of-possession, and applies state mutations network-wide.

### 5. Technical Specifications
- **Authoritative Specification Document**:
  - Published [`04_key_rotation_and_remediation.md`](file:///home/mreugenej7/git/randbotd/docs/specs/ca/04_key_rotation_and_remediation.md) detailing the offer-level key life-cycle model, Proof-of-Possession semantics, distrust strike reset invariants, and anti-solipsism rules.

## Retrocompatibility Guarantees

- **Database Schemas**:
  - `CertificateOffer.public_key` employs `#[serde(default)]` with empty vectors defaulting to previous catalog hashing semantics, ensuring seamless non-destructive loading of all pre-existing `ca_offers.json` databases from 3.4.x and 3.5.x.
  - `key_rotations.json` operates as an additive subtable initialized gracefully on first run.
- **Wire Framing**:
  - `PAYLOAD_TYPE_KEY_ROTATION` (16) is purely additive and safely handled across all existing gossip router installations.
