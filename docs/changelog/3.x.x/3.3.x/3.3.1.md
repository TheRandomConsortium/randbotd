# Changelog — randbotd 3.3.1

**Released:** 2026-08-24

## Summary

This patch release implements **`CA-15` (P2P Authority Information Access & P2P OCSP Extension Engine)**, completing Phase 2 of the CA subsystem milestone. It extends RFC 5280 and RFC 6960 Authority Information Access (AIA) mechanics by embedding decentralized `randbotd://` P2P swarm URIs into X.509 v3 root and leaf domain certificates for parent CA certificate resolution (`id-ad-caIssuers`) and real-time P2P revocation status lookups (`id-ad-ocsp`).

---

## Key Features & Enhancements

### 1. P2P Authority Information Access (AIA) & P2P OCSP Engine (`CA-15`)

- **RFC 5280 §4.2.2.1 Standard ASN.1 AIA Encoding**:
  - Implemented `encode_authority_info_access` and `encode_access_description` in `src/pki/cert/extensions.rs`, generating compliant `AuthorityInfoAccessSyntax` (`SEQUENCE OF AccessDescription`).
  - Strict compliance with RFC 5280 §4.2.2.1: marked `critical = FALSE` ensuring interoperability across standard and P2P-aware parsers.
  - Access Locations mapped to standard `GeneralName` Context-Specific Tag `[6]` (`uniformResourceIdentifier`).
- **Standardized `randbotd://` Swarm URIs**:
  - `id-ad-caIssuers` (`1.3.6.1.5.5.7.48.2`): `randbotd://ca/<ca_id_hex>/cert`
  - `id-ad-ocsp` (`1.3.6.1.5.5.7.48.1`): `randbotd://ca/<ca_id_hex>/ocsp`
- **Builder Integration**:
  - Integrated AIA extension construction directly into `X509CertificateBuilder::build_root_ca_certificate` and `build_domain_leaf_certificate`.
- **Cleanliness & Standards Alignment**:
  - Maintained zero compiler warnings under `cargo clippy -- -D warnings`, verified strict code formatting via `cargo fmt`, and validated repository cleanliness limits ($\le 500$ lines per file, $\le 9$ entries per directory).
