# Changelog — randbotd 3.5.0

**Released:** 2026-09-17

## Summary

This minor release introduces the **CA-07: Bad-Domain Purge Engine**, providing decentralized Certificate Authorities with cryptographic, tamper-evident mechanisms to publicly repudiate, blacklist, and purge domains known to be abusive, compromised, or infringing prior to certificate issuance.

Because payments (`PAY-06`) are deferred to Phase 9 and public certificate emission is not yet live, CA-07 is deployed in wireframed mode. The implementation guarantees strict retrocompatibility for already-deployed CAs, introduces a hash-chained monotonic sequence model with dynamic Proof-of-Work (PoW) scaling, isolates purge state into a dedicated database subtable (`domain_purges.json`), and integrates P2P gossip broadcasting and IPC management endpoints.

---

## Key Features & Enhancements

### 1. Cryptographic Bad-Domain Purge Records (`CA-07`)
- **Monotonic Hash-Chained Purge Records**:
  - Implemented `DomainPurgeRecord` in `src/pki/purge/mod.rs` featuring sequential monotonic indexing (`purge_seq`), SHA-256 parent hash chaining (`prev_purge_hash`), timestamp bounds, and Ed25519 / Post-Quantum signature binding directly against the emitting CA keypair.
  - Prevents purge omission, state fork equivocation, and out-of-order execution across distributed nodes.
- **Categorized Purge Reasons & Structured Evidence**:
  - Supports `PurgeReason` variants (`PrivateKeysCompromised`, `PhishingOrMalware`, `DomainOwnershipRevoked`, `TldSeizureOrSunset`, `SanctionOrLegalOrder`, `CaPolicyViolation`).
  - Embeds structured `DomainPurgeEvidence` containing RFC 3161 timestamps, third-party scanner hashes, or external cryptographic strike evidence.

### 2. Dynamic Proof-of-Work (PoW) Anti-Spam Scaling
- **Rate-Limiting CA Purge Emissions**:
  - Implemented anti-spam PoW challenge resolution (`compute_purge_challenge`, `solve_purge_pow`, `verify_purge_pow`) with dynamic logarithmic difficulty scaling:
    $$\text{Difficulty} = 12 + \lfloor 2 \cdot \log_2(N_{\text{active}} + 1) \rfloor + (\text{if evidence} \{ 0 \} \text{ else } \{ 4 \})$$
  - Prevents CAs from spamming purges without computational investment while granting difficulty relief when verifiable strike evidence is provided.

### 3. Isolated Subtable Architecture (`domain_purges.json`)
- **Zero State Duplication**:
  - Stored purge records exclusively in `domain_purges.json` managed by `PurgeSubtable` in `src/storage/db/purge_subtable.rs`.
  - Avoided mutating or duplicating purge lists within `ca_declarations.json`, preserving existing database schemas and eliminating cross-table synchronization hazards.
- **Full Backward Compatibility**:
  - Verified that existing node databases load cleanly without migrations or destructive edits.

### 4. P2P Gossip Broadcast & Ingestion
- **Gossip Protocol Extension**:
  - Allocated `PAYLOAD_TYPE_DOMAIN_PURGE = 15` in `src/net/gossip.rs`.
  - Added routing and broadcast handling in `src/net/router/broadcast/mod.rs`, verifying CA ownership, intermediate CA permitted subtrees, hash chain links, PoW difficulty, and cryptographic signatures before committing purges to local state.
- **Pre-Issuance Purge Guard**:
  - Integrated `is_domain_purged` check into `handle_generate_domain_cert` (`src/net/ipc/handler/offer.rs`), preventing certificates from being issued for blacklisted or purged domains.

### 5. IPC Control Endpoints & Testing Tools
- **Daemon Management via IPC**:
  - Extended IPC with `PurgeDomain`, `GetPurge`, `ListPurges`, and `BroadcastPurge` commands.
  - Added CLI test utilities in `src/net/ipc/handler/purge.rs`.

### 6. Architectural Integrity & Validation Skill
- **Skill Definition**:
  - Codified the mandatory 4-phase validation and release pipeline (`randbotd-validation-and-release`).
  - Enforces real modularization, interfaces, and architecture; strictly forbids line-collapsing or minification tricks; and mandates documented justification for any compiler annotations.
