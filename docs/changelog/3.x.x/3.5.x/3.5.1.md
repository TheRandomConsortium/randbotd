# Changelog — randbotd 3.5.1

**Released:** 2026-09-17

## Summary

This patch release resolves a critical cryptographic mismatch in the Bad-Domain Purge IPC handler (`CA-07`), introduces an extensible `IpcContext` interface across all domain handlers, isolates pre-issuance domain purge validation for upcoming Phase 7 review, and connects purge IPC commands to automatic P2P swarm broadcast triggers.

---

## Key Features & Enhancements

### 1. Authoritative CA Owner Signing for Domain Purges (`CA-07`)
- **Node Identity Signing Key Integration**:
  - Corrected `PurgeHandler::handle_purge_domain` to sign `DomainPurgeRecord` with the active node identity's private signing key (`NodeIdentity::signing_key()`) rather than generating transient keypairs.
  - Added strict ownership validation checking that `compute_ca_id(&ca_decl.subject.common_name, &my_pubkey) == ca_id` prior to issuing purges, rejecting unauthorized purge attempts at the IPC boundary.
  - Ensures that when purges are broadcast across the P2P swarm, the gossip message originator and the cryptographic signature on the record match identically, allowing all peer nodes to verify and ingest the event.

### 2. Extensible `IpcContext` Architecture
- **Interface Decoupling**:
  - Replaced rigid, expanding parameter lists in `IpcHandler::handle` with a clean `IpcContext<'a>` structure holding references to `Phonebook`, `Database`, and `NodeIdentity`.
  - Updated `PeerHandler`, `CaHandler`, `OfferHandler`, `ProofHandler`, `CrlHandler`, and `PurgeHandler` to consume `IpcContext`.
  - Added `.with_identity(identity)` to `IpcServer` and threaded `Arc<NodeIdentity>` from daemon startup in `main.rs`.

### 3. Pre-Issuance Purge Policy Isolation & CA-Scoped Subtable Queries
- **Isolation for Phase 7 Review**:
  - Extracted pre-issuance domain validation into `OfferHandler::is_domain_blocked_by_purge_policy`, clearly isolating the check and documenting that purging is not meant to be an unconditional network-wide veto.
  - Added `Database::is_domain_purged_by_ca(&self, ca_id, domain, now)` in `purge_subtable.rs` for authoritative CA-scoped lookups, establishing the foundation for future federated CA trust networks and fairban matchmaking.

### 4. Swarm Broadcast Triggers on Purge Commands
- **Instant P2P Propagation**:
  - Wired `IpcCommand::PurgeDomain` and `IpcCommand::BroadcastPurge` into the IPC control server's broadcast channel, immediately signaling `broadcast_published_pki_entities` to disseminate new purges to connected peers without daemon restarts.
