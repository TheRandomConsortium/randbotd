# Changelog — randbotd 3.4.0

**Released:** 2026-09-09

## Summary

This minor release implements **`CA-04` (P2P Cert Chain Broadcasting)**, enabling decentralized public key infrastructure distribution across the `randbotd` P2P gossip swarm. It introduces automated broadcasting and recipient validation of published non-draft CA declarations (`PAYLOAD_TYPE_CA_DECLARATION = 3`), intermediate certificate chains (`PAYLOAD_TYPE_CERT_CHAIN = 4`), and RFC 5280 X.509 v2 Certificate Revocation Lists (`PAYLOAD_TYPE_CRL_BROADCAST = 14`). It also implements standard CRL Distribution Points (CDP, OID `2.5.29.31`) in certificate builders, persistent JSON subtable storage for chains and CRLs (`cert_chains.json`, `crls.json`), comprehensive certificate chain verification, and IPC control endpoints for CA operators.

---

## Key Features & Enhancements

### 1. P2P Cert Chain Broadcasting (`CA-04`)

- **Automated Gossip Broadcast of Published Non-Draft CAs**:
  - Automatically broadcasts published CA declarations across the UDP gossip network upon startup and IPC invocation.
  - **Draft Protection**: Only non-draft CAs are propagated across the swarm; draft CAs are strictly rejected and dropped from network dissemination.
  - Recipient nodes independently validate incoming CA declarations: verifies deterministic `ca_id` calculation (`SHA-256(custodian_peer_id || root_public_key)`), ISO 3166-1 alpha-2 country codes, issuer DN, and capability limits before committing to `ca_declarations.json`.
- **RFC 5280 X.509 v2 Certificate Revocation List (CRL) Engine**:
  - Full ASN.1 DER and PEM (`-----BEGIN X509 CRL-----`) encoder in `src/pki/crl.rs`.
  - Implements standard RFC 5280 reason codes (`KeyCompromise`, `CACompromise`, `AffiliationChanged`, `Superseded`, `CessationOfOperation`, `CertificateHold`, `PrivilegeWithdrawn`, etc.).
  - Signature generation and verification across all supported cryptographic algorithms (Ed25519, ECDSA P-384, RSA-4096, ML-DSA-44).
  - P2P broadcast frame handling (`PAYLOAD_TYPE_CRL_BROADCAST = 14`) with cryptographic signature validation against the issuing CA before saving to `crls.json`.
- **CRL Distribution Points (CDP) Extension**:
  - Added X.509 v3 extension `cRLDistributionPoints` (OID `2.5.29.31`) in `src/pki/cert/extensions.rs`.
  - Automatically embedded in root and leaf certificate generation with deterministic P2P distribution URI `randbot://crl/<ca_id>`.
- **Certificate Chain Validation Engine**:
  - Implemented `CertificateChain` path verification in `src/pki/chain.rs`: verifies issuer/subject matching, validity time windows, signature links from leaf through intermediate certificates to root trust anchors, and WoT critical extensions.
  - *Note on Intermediaries*: Dead-code allowances on intermediate certificate builders and chain paths are documented as permitted ahead of `CA-11` (Distributed Custodian Swarms).

### 2. Persistent Subtable Storage (`cert_subtable.rs`)

- **Persistent Chains and CRLs**:
  - Added `cert_chains.json` and `crls.json` subtable management in `src/storage/db/cert_subtable.rs`.
  - Implemented lookup and revocation verification helpers (`is_serial_revoked`, `is_cert_revoked_any`).

### 3. IPC Management Endpoints

- Added new IPC commands in `src/net/ipc/handler/crl.rs`:
  - `BroadcastCa`: Broadcasts a local published non-draft CA to all active peers (rejects drafts).
  - `BroadcastCertChain`: Distributes an intermediate certificate chain to swarm peers.
  - `IssueCrl`: Issues, signs, persists, and broadcasts a fresh RFC 5280 CRL for a CA.
  - `GetCrl`: Retrieves the latest CRL for a CA by ID.
  - `VerifyCertChain`: Validates certificate chain signatures and checks against active CRLs.
