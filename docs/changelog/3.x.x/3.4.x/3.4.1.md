# Changelog — randbotd 3.4.1

**Released:** 2026-09-10

## Summary

This patch release hardens the production deployment readiness for the **Final Production Root CA** launch. It introduces reactive IPC broadcast event streaming for instantaneous swarm propagation upon CA publication, non-blocking lock scoping across all database subtables to eliminate I/O lock contention during peer queries, immutable event log error logging for invalid or unmapped CA declarations, and dynamic CLI version synchronization.

---

## Key Features & Enhancements

### 1. Reactive IPC Swarm Broadcast (`CA-04`)
- **Instant Propagation on Publication**:
  - Connected the local IPC control server (`IpcServer`) to the P2P broadcast engine via an asynchronous `tokio::sync::mpsc` event channel.
  - Publishing a non-draft CA via IPC (`PublishCa`), issuing a CRL (`IssueCrl`), or triggering explicit broadcasts (`BroadcastCa`, `BroadcastCertChain`) immediately triggers an asynchronous multi-hop gossip broadcast across all connected peers without requiring a daemon restart or waiting for polling cycles.
  - Eliminated legacy dummy genesis payloads during empty CA broadcasts, preventing bogus gossip packets.

### 2. Subtable Non-Blocking Lock Scoping & I/O Optimization
- **Lock Guard Isolation**:
  - Scoped `RwLock` write guards across `ca_subtable.rs`, `cert_subtable.rs`, and `offer_subtable.rs` so in-memory mutations release locks *prior* to disk serialization and I/O writes.
  - Eliminates lock starvation for concurrent P2P gossip readers querying CAs, offers, or CRLs while large database tables are being persisted to disk.

### 3. Immutable Event Log & Diagnostic Error Ingestion
- **Robust Ingestion Auditing**:
  - `handle_ca_declaration_packet` now records all incoming CA declaration wire frames into the immutable `event_log.jsonl` (flagged as bullshit if deserialization, country code, or deterministic `ca_id` binding fails).
  - Explicit diagnostic error logging replaces silent drops when incoming CA declarations cannot be mapped.
  - Enhanced `EventLogEntry::verify_signature` in `src/net/history.rs` to transparently verify both standard wire frames and gossip wire framing signatures.

### 4. Dynamic CLI Version Synchronization
- **Dynamic Versioning in CLI**:
  - Updated `src/cli.rs` to derive version information directly from `Cargo.toml` (`#[command(version)]`), ensuring `randbotd --version` accurately reports the active package release.

### 5. Architectural Clarifications
- **Horizontal Scaling vs. Vertical Sub-CA Delegation**:
  - Updated `docs/specs/ca/02_ca_entities_and_operational_model.md` Section 3.1.2 detailing why Multi-Offer catalogs obsolete product-based intermediate CAs, and clarifying the architectural bifurcation between `CA-11` (FROST horizontal threshold co-signers) and hierarchical vertical sub-CA delegation with `CA-14` Name Constraints.

## Retrocompatibility Guarantees

> [!IMPORTANT]
> The Root CA published following this release is **FINAL and PERMANENT**. All database schemas (`ca_declarations.json`, `ca_offers.json`, `cert_chains.json`, `crls.json`) are now strictly covered by the backward compatibility invariant. Any future schema evolutions will provide non-destructive automatic migrations.
