# Changelog — randbotd 3.2.0

**Released:** 2026-08-20

## Summary

This minor release introduces **CA-14 (Subtree Name Constraints Engine)** providing declarative domain coverage scopes (`CertificateCoverageScope`) for CA offers and standard RFC 5280 Name Constraints validation (`permittedSubtrees`) for Intermediate CAs. It also introduces configurable entropy fallbacks for node mnemonic generation (`[entropy] allow_fallback`), rapid pre-seeded testing optimizations, and strict codebase clutter minimization.

---

## Key Features & Enhancements

### 1. Subtree Name Constraints & Coverage Scopes (`CA-14`)

- **Declarative Coverage Scopes (`CertificateCoverageScope`)**: Added four standard-aligned domain coverage profiles to Certificate Offers:
  - `SingleFqdn`: Exact single domain coverage.
  - `WildcardApex`: Apex domain plus 1-level wildcard (`*.domain.tld`).
  - `MultiSan`: Multi-domain SAN issuance up to `max_sans` with configurable wildcard permissions.
  - `SubtreeDelegation`: Subtree-restricted delegation for Intermediate CAs.
- **Intermediate CA Namespace Restrictions**: Enforced RFC 5280 §4.2.1.10 name constraint rules (`permitted_subtrees`) on Intermediate CA declarations (`is_intermediate = true`), rejecting non-intermediate Root CAs attempting to advertise unproven subtree constraints.
- **Dynamic Permitted Subtree Matching**: Implemented RFC 5280 subdomain suffix matching (`is_domain_permitted` and `is_domain_in_permitted_subtrees`).
- **Standardized OID Constants**: Added `OID_NAME_CONSTRAINTS = "2.5.29.30"` with critical extension semantics (`NAME_CONSTRAINTS_CRITICAL = true`).

### 2. Configurable Entropy Fallback Engine (`[entropy]`)

- **Project Gutenberg Live Status & Resilience**: Project Gutenberg (`https://www.gutenberg.org/dirs/`) is the primary live entropy pool for generating 256-bit mnemonic recovery phrases. Because Project Gutenberg experienced a temporary server outage during development, a configurable fallback engine was introduced.
- **Information-Theoretic Security Equivalence**: Because Shannon entropy calculation mathematically depends purely on CSPRNG word selection over a pool of distinct vocabulary ($H = \sum \log_2(N)$ bits), sampling from any corpus with more than one word generates the exact same mathematical security guarantees.
- **Configurable Fallback Toggle**: `allow_fallback` defaults to `false` in production (enforcing live scraping). When `--allow-entropy-fallback` CLI flag or `[entropy] allow_fallback = true` in `randbotd.toml` is enabled, the driller falls back to sampling from Timothy C. May's *The Crypto Anarchist Manifesto* (1988) if upstream servers are unreachable.
- **Active Chore `ENTROPY-01`**: Logged future support for operator-defined plaintext entropy source URLs (HTML, CSV, TXT, JSON) in `CHORES.md`.

### 3. Test Suite Speed & Clean Architecture

- **Pre-Seeded IPC Test Helpers**: Initialized test phonebooks with static pubkey entries, completely bypassing slow key-derivation loops during test runs.
- **Fast IPC Test Profile**: Gated heavy socket-binding end-to-end IPC tests behind `cargo test --features full-suite` with user-friendly notices for standard `cargo test` executions.
- **Dead Code Cleanup & Unified Constructors**: Consolidated `CaDeclaration::new` and `CertificateOffer::new` into single canonical constructors, purging redundant wrappers.
