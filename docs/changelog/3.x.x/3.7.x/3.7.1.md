# Changelog — randbotd 3.7.1

**Released:** 2026-09-22

## Summary

This patch release hardens **CA-11: Distributed Custodian Swarm & Threshold Key Delegation Engine** with authentic cryptographic certificate verification and swarm network capability validation:

1. **Pure Rust ASN.1 DER Capability Certificates**: Replaced synthetic mock certificate placeholders with real X.509 DER certificates generated directly via [`X509CertificateBuilder::build_domain_leaf_certificate`](file:///home/mreugenej7/git/randbotd/src/pki/cert/builder.rs), binding the challenge nonce inside a protocol mock domain (`mock-{nonce}.randbotd.internal`) and RFC 5280 extensions.
2. **Zero-OpenSSL Pure Rust Verification**: Both the delegating CA and any peer node in the swarm can download and cryptographically verify the capability certificate's signature and nonce across all supported algorithms (Ed25519, ECDSA P-384, RSA-4096, ML-DSA-44) in pure Rust without external CLI tools.
3. **Mandatory Worker CA Network Coverage**: Enforces that candidate custodian workers must be registered, published CAs whose declared network capabilities (`supported_domain_networks`) cover 100% of the networks supported by the delegating CA (Clearnet, Handshake, Tor, I2P). Non-compliant petitions are dropped silently.

## Key Changes & Enhancements

### 1. Genuine X.509 DER Capability Certificates (`src/pki/swarm/mock_cert.rs`)
- **Direct CA-05 Builder Integration**:
  - `build_mock_capability_certificate` generates an ephemeral keypair for the catalog offer's algorithm and calls `X509CertificateBuilder::build_domain_leaf_certificate` under the target CA's subject DN.
  - Automatically incorporates all standard extensions (Basic Constraints, Key Usage, EKU, SANs, SKI, AKI, WoT, AIA, CDP) and the Domain Proof Binding extension (`challenge_nonce:{nonce}`).
- **Pure Rust Signature & Nonce Verification**:
  - `verify_mock_capability_certificate` parses ASN.1 DER framing, verifies cryptographic signature validity using `verify_signature_by_algorithm`, and asserts presence of the challenge nonce in the TBS certificate payload.
  - Enables decentralized auditability: any peer in the swarm can verify candidate certificates retrieved over TCP.

### 2. Worker CA Network Capability Invariant
- **Pre-Qualification Check**:
  - In Step 1 (`handle_custodian_contract_packet`), the CA verifies that `contract.worker_pubkey` belongs to a registered, published (non-draft) CA in the local consensus database.
  - Asserts that `worker_ca.supported_domain_networks` is a superset of `ca.supported_domain_networks`.
  - Workers lacking support for any network required by the CA (e.g. Tor or I2P) are silently dropped with zero response.
- **Pre-Tested Network Guarantee**:
  - Under `randbotd` architecture, declaring support for any network overlay (`Clearnet`, `Tor`, `I2P`, `Handshake`) in a CA declaration requires passing local connectivity validation during node configuration (verifying active Tor SOCKS5 proxies, I2P SAM bridge interfaces, and DNS resolvers).
  - Therefore, a published CA declaration is an authoritative, already-tested commitment that the worker node has active operational capability to perform domain proofs and route challenges over those networks.
