# randbotd v1.3.0 Release Changelog

### 🔐 `CA-02` Cryptographic Agility Suite & Post-Quantum Cryptography

Version 1.3.0 delivers **`CA-02`: Cryptographic Agility Suite**, introducing multi-algorithm key generation, digital signatures, NIST Post-Quantum Cryptography (PQC), Argon2id masterpass key encryption, CA draft mode, in-place CA editing, and P2P phonebook self-exclusion hygiene.

---

## 🚀 Key Improvements & Architecture

### 1. `CA-02`: Cryptographic Agility Engine (`src/crypto/agility.rs`)
- **Multi-Algorithm Key & Signing Engine (`CaKeyPair`)**:
  - **Ed25519** (Pure Ed25519 / RFC 8032) -> Official OID `1.3.101.112`
  - **ECDSA P-384** (secp384r1 + SHA-384 / RFC 5480) -> Official OID `1.2.840.10045.4.3.3`
  - **RSA-4096** (RSA 4096-bit + SHA-256 / PKCS#1 v1.5) -> Official OID `1.2.840.113549.1.1.11`
  - **ML-DSA-44** (NIST FIPS 204 Dilithium2 PQC Digital Signature) -> Official OID `2.16.840.1.101.3.4.3.17`
- **Post-Quantum Cryptography (ML-DSA-44 / Dilithium2)**:
  - Added **ML-DSA-44 (Dilithium2)** as the official Post-Quantum Digital Signature algorithm for CA certificate generation (`sign`) and verification (`verify`).
> [!WARNING]
> **Browser Compatibility Warning**: Standard legacy web browsers (Chrome, Firefox, Safari) will NOT natively parse or accept raw Post-Quantum ML-DSA certificates for public web TLS. ML-DSA key material is intended for `randbotd` P2P node-to-node security or custom proxy daemons (`circlejerk-protocol` / `juanita-companion`). For public web browser compatibility, select **ECDSA P-384** or **RSA-4096**.
- **Argon2id KDF + ChaCha20-Poly1305 Encrypted Key Storage**:
  - All CA private keys (`ca_key_<ca_id>.enc`) are encrypted at rest using **Argon2id KDF + ChaCha20-Poly1305 AEAD**, bound to the node master password (`RANDBOTD_MASTERPASS` or `/etc/randbotd/masterpass.cred`), zeroizing private key memory on drop.

### 2. CA Draft Mode & In-Place Editing (`src/crypto/ca.rs`)
- **Draft Status Flag (`is_draft`)**: Node operators can publish CAs in draft mode (`"is_draft": true`) and edit Distinguished Name fields in-place via `ca_id_hex` before finalizing public release (`"is_draft": false`).

### 3. P2P Phonebook Ingestion Hygiene (`src/net/phonebook.rs`)
- **Zero-Pubkey & Self-Exclusion Guards**:
  - `upsert_peer` rejects zero-pubkey (`00000000...`) placeholders and node's own public key/address (`my_pubkey_hex`) at ingestion.
  - Zero-pubkey entries and self-referential entries never pollute `peers.json` on disk or memory tables.

> [!IMPORTANT]
> **Operator Action Required for Existing `peers.json`**:
> If your local `peers.json` contains legacy zero-pubkey entries (`00000000...`) or your own local loopback socket (`127.0.0.1:43212`), remove `peers.json` (`rm peers.json`) and restart `randbotd`. The daemon will automatically perform a clean P2P bootstrap and populate verified remote peer keys.

### 4. Modular IPC Architecture ([`src/net/ipc/`](file:///home/mreugenej7/git/randbotd/src/net/ipc/))
- Refactored single IPC file into modular directory structure (`mod.rs` and `handler.rs`), adhering to repository cleanliness guidelines (all files <= 500 lines).
