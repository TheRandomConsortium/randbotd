# randbotd v1.4.1 Release Changelog

### 🌐 Real Network Resolution Engine & Handshake Arbitrary TLD Support (`CA-03`)

Version 1.4.1 refactors **`CA-03`: Multi-Network Domain Proofs Engine** to eliminate static domain TLD string matching in favor of real, active network queries for non-hidden service domains.

---

## 🚀 Key Architectural Improvements

### 1. Real Active Network Resolution (`src/crypto/proof.rs` & `src/crypto/proof_net.rs`)
- **No Static TLD Assumptions**:
  - Removed hardcoded TLD suffix string matching (`.hns`, `.randºm`, `.mreugenej7`, `.com`, `.org`, etc.).
  - Only hidden services (`.onion` and `.i2p`) are classified by static suffix.
- **Dynamic Resolution Priority (`DomainNetworkType::resolve_network_type`)**:
  - **Step 1 (Clearnet)**: Sends real UDP DNS query to **Upstream Clearnet DNS (Quad9 `9.9.9.9:53`)** first. If Upstream DNS returns valid records (`NOERROR` + answers), classifies domain as `Clearnet`.
    > [!WARNING]
    > **Trustworthy Upstream DNS Requirement**: `upstream_dns_resolver` MUST only be configured with trustworthy, non-intercepting resolvers (such as Quad9 `9.9.9.9:53`). Local ISP DNS servers with catch-all search portals or DNS hijacking will falsely resolve non-existent names and break Handshake and domain proof verification.
  - **Step 2 (Handshake)**: If Upstream Clearnet DNS returns `NXDOMAIN` or fails, sends real UDP DNS query to **Handshake DNS daemon (`127.0.0.1:53493` `hnsd`)**. If Handshake DNS resolves the record, classifies domain as `Handshake` (supporting arbitrary root TLDs such as `.randºm`, `.mreugenej7`, `.crypto`, etc.).
  - **Step 3 (Fast Abort)**: If neither Upstream Clearnet DNS nor Handshake DNS resolves the domain (and HTTP Nonce fallback fails), aborts fast with `ProofError::UnresolvableDomain("Domain is unresolvable or unsupported")`.


### 2. Network Helper Extraction (`src/crypto/proof_net.rs`)
