# randbotd v1.4.3 Release Changelog

### 🔒 Low-Level `rustls` TLS ALPN Protocol Negotiation & Handshake IP Resolution (`CA-03`)

Version 1.4.3 replaces standard HTTP request header mockups with **real TLS ClientHello ALPN protocol negotiation** via `rustls` and implements **active Handshake DNS IP resolution** for HTTP Nonce fallback requests.

---

## 🚀 Architectural Refactorings

### 1. Real TLS ALPN ClientHello Negotiation (`src/crypto/proof_tor.rs`)
- **Underlying TLS Engine**: Dropped higher-level HTTP header simulations in favor of low-level `rustls::ClientConfig` stream negotiation.
- **ALPN Protocol Identifiers**:
  - `b"randbotd-alpn/1"`
  - `b"acme-tls/1"`
- **Native SOCKS5 Proxy Socket (`connect_socks5_proxy`)**:
  - Implemented low-level TCP SOCKS5 handshake (`0x05`, `0x01`, `0x03` ATYP Domain) for Tor `.onion` endpoints over port 443.
  - Wraps the SOCKS5/TCP socket in a `rustls::ClientConnection` stream to conduct true TLS ALPN handshakes.

### 2. Handshake Domain HTTP Fallback IP Resolution (`src/crypto/proof_net.rs`)
- **Active HNS Daemon IP Query (`resolve_hns_ip`)**:
  - Resolves Handshake domains (e.g., `.randºm`, `.hns`) to their IPv4 `A` record by querying the local Handshake daemon `hnsd` (`127.0.0.1:53493`).
- **Target IP HTTP Routing**:
  - Dispatches HTTP Nonce fallback requests directly to the target IP address `http://<ip>/.well-known/randbotd-proof` with the `Host: <domain>` header attached, bypassing system DNS limitations for custom root TLDs.

### 3. Modular File Separation & Cleanliness Compliance (`src/crypto/proof_tor.rs` & `src/crypto/proof_i2p.rs`)
- Extracted Tor TLS ALPN logic into [`src/crypto/proof_tor.rs`](file:///home/mreugenej7/git/randbotd/src/crypto/proof_tor.rs).
- Extracted I2P SAM v3.0 bridge logic into [`src/crypto/proof_i2p.rs`](file:///home/mreugenej7/git/randbotd/src/crypto/proof_i2p.rs).
- All source files remain strictly $\le 500$ lines, and `src/crypto/` remains $\le 9$ items.
