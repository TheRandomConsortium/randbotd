# Changelog — randbotd 1.5.0

**Released:** 2026-08-13

## Summary

This release completes the CA-03 Multi-Network Domain Proofs Engine by wiring the
Handshake DNS resolution stack to the full `HandshakeConfig` target and mode
configuration introduced in 1.4.x. It also restructures the proof network modules
for cleaner separation of responsibilities.

---

## New Features

### Handshake DNS Target & Mode Dispatch (`HandshakeConfig`)

`HandshakeConfig` now exposes two resolution helpers consumed by all Handshake DNS
calls:

- **`resolve_target_addr()`** — resolves the configured target to a concrete
  `"host:port"` string:
  - `"daemon"` (default) → `127.0.0.1:<hns_dns_port>` (default `53493`)
  - `"system"` → returns the literal string `"system"`, which the UDP dispatcher
    maps to `127.0.0.53:53` (systemd-resolved stub)
  - Any other value — treated as a custom endpoint; `:53` is appended automatically
    if no port is present (e.g. `"hdns.io"` → `"hdns.io:53"`)

- **`is_doh_mode()`** — returns `true` when `hns_dns_mode` is `"doh"` or `"https"`

### DNS-over-HTTPS (DoH) Support (`src/crypto/dns.rs`)

`send_dns_query_payload()` dispatches DNS wire-format queries over either transport:

- **UDP** — standard binary DNS packet sent to the resolved target address
- **DoH** — wire-format query POSTed to `https://<target>/dns-query` with
  `Content-Type: application/dns-message` and `Accept: application/dns-message`,
  response bytes parsed identically to UDP

All three DNS entry-points (`check_dns_resolves`, `send_dns_txt_query_config`,
`resolve_hns_ip`) dispatch through `send_dns_query_payload`, inheriting DoH or UDP
automatically from config.

> [!IMPORTANT]
> `upstream_dns_resolver` must point to a reliable upstream recursive resolver
> (e.g. Quad9 `9.9.9.9:53`). Using a catch-all ISP portal DNS will cause
> Handshake verification to silently succeed for unresolvable domains, breaking
> the clearnet/Handshake classification logic.

## Module Restructuring

| Old location | New location | Reason |
|---|---|---|
| `src/crypto/proof_tor.rs` | `src/crypto/proof_overlay.rs` | Combined with I2P |
| `src/crypto/proof_i2p.rs` | `src/crypto/proof_overlay.rs` | Both are overlay transports |
| *(new)* | `src/crypto/dns.rs` | Wire-format DNS helpers extracted from `proof_net.rs` |

`src/crypto/proof_net.rs` now only contains the proof response types and HTTP nonce
fetching. DNS wire queries live in `src/crypto/dns.rs`.

---

## Bug Fixes

- Handshake domain resolution previously hardcoded `127.0.0.1:53493` regardless of
  config. All three resolution paths (`resolve_network_type`, `verify_active_domain_control`,
  `resolve_hns_ip`) now use `resolve_target_addr()` and `is_doh_mode()` from
  `HandshakeConfig`.
