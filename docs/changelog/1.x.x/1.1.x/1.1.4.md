# randbotd v1.1.4 Release Changelog

### ⚡ Out-of-Order Staging & Bullshit Event Ingestion for Network-Wide Ponderation

Version 1.1.4 introduces out-of-order event staging (`pending_unverified`) and **bullshit event ingestion** (`is_bullshit: bool`). Rather than dropping bad messages or using local banlists, bad messages are recorded in the event log so the entire P2P network syncs the exact same ledger and penalizes the originator's ponderation/reputation.

---

## 🚀 Key Improvements & Architecture

### 1. Out-of-Order Staging Pool (`src/storage/db/mod.rs`)
- **Authenticity-First Verification**: `entry.verify_signature()` is checked immediately upon receipt.
- **Future Sequence Staging (`entry.seq > expected_seq`)**: Out-of-order events are buffered in `pending_unverified` sorted by sequence number rather than being rejected.

### 2. Bullshit Event Ingestion & Reputation Ponderation
- **Network-Wide Consensus Ledger**: Hard banlists/blacklists are completely eliminated. If an originator key produces a message with a broken `prev_hash` link or invalid sequence chain, the message is **ingested into the database marked as `is_bullshit: true`**.
- **Network-Wide Syncing**: Because the bad message is ingested into the event log, all nodes in the swarm sync the exact same sequence via anti-entropy range sync.
- **Dynamic Originator Ponderation**: Any node can compute an originator's reputation score (`db.get_originator_reputation(originator) -> (valid_count, bullshit_count)`). Bad behavior lowers their consensus weighting across the entire network without needing local banlists.
