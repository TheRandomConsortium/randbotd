# randbotd v1.1.1 Release Changelog

### 🌐 Core P2P Network Infrastructure & Anti-Entropy Sync Completion

Version 1.1.1 delivers the full implementation of the P2P core network infrastructure (`NET-04`, `NET-05`, `NET-08`, `NET-09`), introducing an embedded transactional database, persistent sync offset pagination, node-scoped anti-entropy event log synchronization, overlay peer discovery, Unix domain socket IPC daemon control, and peer IP reflection address discovery with privacy controls.

---

## 🚀 Key Features & Architectural Improvements

### 1. Embedded Transactional Database Engine & Sync Offset Persistence (`NET-04` / `src/storage/db.rs`)
- **JSONL Event Log Storage**: Implemented embedded transactional database engine (`Database`) in `base_state_dir`, storing raw wire-format `EventLogEntry` consensus items (`event_log.jsonl`).
- **Complete Wire Ledger Strategy**: Preserves raw cryptographic signatures and byte representations for offline/bootstrapping nodes to verify hash linkage and Ed25519 signatures independently before ingesting events.
- **Persistent Sync Offset Pagination (`sync_offset.state`)**: Persists the atomic sync pagination offset on disk across daemon process restarts, ensuring round-robin anti-entropy sweeps resume seamlessly after process reboot.

### 2. Node-Scoped Monotonic Chains & Anti-Entropy Exchange (`NET-05` / `src/net/history.rs`, `src/net/router/`)
- **Per-Originator Monotonic Validation**: Sequence numbers (`seq`) and hash linkages (`prev_hash`) are validated strictly per originator Ed25519 identity key (`[u8; 32]`). Interleaved events from multiple nodes are safely stored in arrival order without sequence conflicts.
- **Transient Traffic Exclusion**: Ephemeral network messages (`PING`, `ADDRESS_ANNOUNCEMENT`, `GET_PEERS_REQ/RESP`, `REFLECT_ADDR_REQ/RESP`) are strictly excluded from storage. Only cryptographically signed consensus events enter the monotonic chain.
- **Dual-Mode Sync Architecture**:
  - *Fast-Path (4-Step Intersect Exchange)*: Uses `OriginatorRangeVector` (`SequenceRange [1..2, 4..5]`) capped at 8 originators per packet for MTU-safe UDP transmission.
  - *Fallback Mode (Iterative Merkle Tree Traversal State Machine)*: When `merkle_root` diverges and sequence fragmentation is high, nodes execute binary Merkle subtree drill-down (`MerkleDrillRequest` / `MerkleDrillResponse`), traversing child nodes (`left_child`, `right_child`) level-by-level to isolate missing sequence numbers without exceeding UDP MTU payload limits.

### 3. Overlay Peer Discovery & Daemon IPC Control Channel (`NET-08` / `src/net/phonebook.rs`, `src/net/ipc.rs`, `src/net/gossip.rs`)
- **8-Random-Peer Sampling (`GetPeersResponse`)**: Responds to `GetPeersRequest` with up to 8 randomly sampled active peer socket addresses from the local `Phonebook`.
- **Capacity-Triggered Keepalive Probes**: Automatically triggers `GetPeersRequest` post-handshake and suppresses periodic checks when active connected peer capacity $\ge N_{\text{target}}$ (8 peers).
- **Additive Daemon IPC Control Server**: Listens on Unix Domain Socket (`randbotd.sock`) or `127.0.0.1:43211` for `randbotctl peer import <peer_addr>` commands to dynamically import peers at runtime without daemon restarts.

### 4. Peer Reflection Probe & IP Privacy Enforcement (`NET-09` / `src/net/gossip.rs`, `src/main.rs`)
- **P2P Peer Reflection Protocol**: Implemented `PAYLOAD_TYPE_REFLECT_ADDR_REQ` and `PAYLOAD_TYPE_REFLECT_ADDR_RESP` to discover public socket addresses without third-party web APIs or STUN servers.
- **Clearnet IP / Domain Warning**: Introduced CLI flag `--do-not-advertise-ip` / TOML setting `do_not_advertise_ip`. Emits a mandatory operator warning if `--do-not-advertise-ip` is enabled while `external_addr` uses a raw IP address or clearnet domain.
