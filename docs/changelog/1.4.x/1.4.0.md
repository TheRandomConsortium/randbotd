# randbotd v1.4.0 Release Changelog

### 🌐 `CA-03` Multi-Network Domain Proofs Engine

Version 1.4.0 delivers **`CA-03`: Multi-Network Domain Proofs Engine**, introducing multi-network domain ownership verification across Clearnet, Handshake, Tor, and I2P, with ISP catchall defense, exponential backoff retries, capability advertising, and diagnostic IPC endpoints.

---

## 🚀 Key Features & Improvements

### 1. `CA-03`: Multi-Network Domain Proof Core Architecture (`src/crypto/proof.rs`)
- **Domain Network Classification (`DomainNetworkType`)**:
  - Classifies domains into `Clearnet`, `Handshake` (`.hns` & custom HNS TLDs), `Tor` (`.onion`), and `I2P` (`.i2p`).
- **ISP Catchall Defense & Resolution Priority**:
  - For non-hidden service domains, queries Handshake daemon (`hnsd`) **FIRST** to resolve Handshake TLDs.
  - If Handshake DNS returns `NXDOMAIN`, queries verified recursive DNS (**Quad9 `9.9.9.9:53`** / **Cloudflare `1.1.1.1:53`**) instead of local ISP DNS, preventing wildcard ISP search portals from hijacking Handshake domain lookups.
  - If neither system DNS nor Handshake DNS resolves the domain (and HTTP Nonce Fallback fails), aborts fast with `ProofError::UnresolvableDomain`.
- **HTTP Nonce Fallback Mechanism**:
  - Provides domain ownership proof for operators without DNS TXT access: CA emits a short-lived nonce, the node signs `randbotd-proof:<domain>:<nonce>` with its Ed25519 identity key, and hosts the signature at `http://<domain>/.well-known/randbotd-proof`.
- **Propagation Retry Engine with Exponential Backoff**:
  - Implemented asynchronous retry calculation ($15\text{s} \times 2^{\text{retry\_count}}$) up to `expires_at` to allow DNS TXT, Tor descriptor, and I2P LeaseSet propagation delays to converge.

### 2. Declarative Handshake Configuration (`src/config.rs`)
- Added `[handshake]` configuration section to `randbotd.toml` (`/etc/randbotd/randbotd.toml`):
  - `hns_dns_port` (default `53493` UDP)
  - `hns_recursive_port` (default `53492`)
  - `hns_dns_mode` (default `"udp"`)
  - `hns_dns_target` (default `"daemon"`)
  - `upstream_dns_resolver` (default `"9.9.9.9:53"`)

### 3. CA Capability Advertising & Network Filtering (`src/crypto/ca.rs`)
- Updated `CaDeclaration` and `ca_declarations.json` schema to include `supported_domain_networks: Vec<DomainNetworkType>`.
- Implemented `validate_against_config`: enforces capability validation at startup and declaration time, failing if a CA advertises `.onion`, `.i2p`, or `.hns` without active daemon/proxy configurations.

### 4. IPC Diagnostic Commands & Mandatory Capabilities (`src/net/ipc/`)
- Added IPC control commands for testing domain proofs:
  - `IpcCommand::ChallengeDomainProof { domain, network_type, ttl_seconds }`
  - `IpcCommand::VerifyDomainProof { challenge_json, txt_record, http_json }`
- Made `supported_domain_networks` parameter mandatory during CA publication, failing if omitted to prevent ambiguous CA declarations.

### 5. Architectural Specification (`ACME-06`)
- Documented `ACME-06` (Emergency Default Fallback CA) short-lived cert lifecycle specification for client-side fallback execution in Phase 5:
  - When a CA is offline or unreachable (`ProofError::BackendUnreachable`), the client generates a short-lived emergency cert (24h TTL) and polls P2P event log stream upon expiration up to `max_emergency_short_certs` before re-entering fair-band CA matching.
